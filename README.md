# Ernie the Evaluator - RFE Comparison Skill

A Claude Code skill that provides objective, systematic evaluation and comparison of Request for Enhancement (RFE) documents generated by different LLM runners.

## Overview

**Ernie the Evaluator** is a specialized Claude skill designed to help teams and individuals compare RFE documents objectively. Whether you're testing different LLM prompts, evaluating different AI models, or comparing human-written vs. AI-generated RFEs, Ernie provides consistent, criteria-based evaluation.

## What Does This Skill Do?

Ernie compares two RFE documents against five professional quality criteria:

1. **Clarity of Purpose and Stakeholder Alignment** - How well the RFE defines the problem, user, and desired outcome
2. **Structural Completeness and Organization** - Document structure, formatting, and logical flow
3. **Actionability and Testability** - Presence of clear, testable acceptance criteria
4. **Language Quality and Communicative Tone** - Professional tone, clarity, and precision
5. **Role Consistency and Perspective** - Maintenance of assigned role's perspective throughout

Each criterion is scored 1-5 with detailed justifications, culminating in a total score and comparative analysis.

### Method 1: Direct Clone (Recommended)
```bash
# Clone this repository into your project

# Copy the .claude directory to your project root
cp -r ernie-rfe-evaluator/.claude /path/to/your/project/
```

### Method 2: Manual Setup
1. Download or clone this repository
2. Copy the `.claude/skills/ernie-rfe-evaluator.md` file to your project's `.claude/skills/` directory
3. If you don't have a `.claude/skills/` directory, create it in your project root

```bash

```

## Usage

Once installed, invoke Ernie from Claude Code using the skill command:

```
/skill ernie-rfe-evaluator
```

Then provide Ernie with:
1. **Original Prompt**: The prompt used to generate both RFEs (as text)
2. **RFE A File Path**: Path to the first RFE document
3. **RFE B File Path**: Path to the second RFE document

### Example Session

```
You: /skill ernie-rfe-evaluator

Ernie: Hello! I am Ernie the Evaluator. To begin the comparative assessment,
please provide the following three items:
1. Task Prompt: [Your prompt here]
2. RFE A File Path: [Path to first RFE]
3. RFE B File Path: [Path to second RFE]

You:
Task Prompt: "As a product manager, create an RFE for adding dark mode support to our web application"
RFE A File Path: ./outputs/claude-rfe.md
RFE B File Path: ./outputs/gpt-rfe.md

Ernie: [Reads both files and provides detailed evaluation...]
```

## Output Format

Ernie provides a structured three-part evaluation:

### 1. RFE A Detailed Scoring Table
| Criterion | Score | Justification |
|-----------|-------|---------------|
| Clarity of Purpose and Stakeholder Alignment | X/5 | ... |
| Structural Completeness and Organization | X/5 | ... |
| Actionability and Testability | X/5 | ... |
| Language Quality and Communicative Tone | X/5 | ... |
| Role Consistency and Perspective | X/5 | ... |
| **Total Score** | **XX/25** | |

### 2. RFE B Detailed Scoring Table
(Same format as above)

### 3. Ultimate Comparison
- **Summary**: Winner and score difference
- **Analysis**: Paragraph explaining why the winner scored higher
- **Actionable Next Step**: Specific recommendation to improve the lower-scoring RFE

## Evaluation Criteria Details

### Clarity of Purpose and Stakeholder Alignment (1-5)
- **5**: Clearly defines the user, the problem, and the desired outcome/goal
- **1**: Vague problem and unclear user/stakeholder

### Structural Completeness and Organization (1-5)
- **5**: Perfectly structured with logical headings, clear sections, and excellent flow
- **1**: Unformatted wall of text with no clear sections

### Actionability and Testability (1-5)
- **5**: Includes clear, generic, and testable requirements that define 'done'
- **1**: Lacks any definable acceptance criteria or next steps

### Language Quality and Communicative Tone (1-5)
- **5**: Concise, precise, and highly professional tone
- **1**: Ambiguous, overly verbose, or unprofessional language

### Role Consistency and Perspective (1-5)
- **5**: Clearly frames the entire request using the assigned role's unique concerns and priorities
- **1**: Shows no distinguishable difference from a default RFE

## Tips for Best Results

1. **Use the Same Prompt**: Ensure both RFEs were generated from identical prompts for fair comparison
2. **Role-Based Prompts**: Include a specific role in your prompt (e.g., "As a security engineer...") to evaluate role consistency
3. **Save RFEs as Files**: Store your RFE outputs as separate files for easy comparison
4. **Document Context**: Keep your original prompts documented alongside RFE outputs for future reference
